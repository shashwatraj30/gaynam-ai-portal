# COMPARE_A - Legacy (localhost:3000) vs New Gyanam AI Portal, catalogue sections 1-5 and 8

Scope: Navigation/Shell (F001-F015), Dashboard (F016-F023), Search Cases (F024-F030), Case Dossier modal (F031-F034), Verify Citation (F035-F039), Precedent History (F061a-c), plus related cross-cutting items (F061 docs link, F086-F088 exports/clipboard, F091-F099 role/landing rules as they touch these tabs).
Method: read the new frontend source (frontend/app/js, css, i18n) and the backend routes it calls (backend/server.py, ui_routes.py, auth.py). Evidence paths are relative to the project root `Gyanam_AI_Portal/`; `js/...` means `frontend/app/js/...`. The running copy at 127.0.0.1:8091 was NOT reachable when I tried (connection refused), so nothing here is from a live UI observation; every status is from code (marked "code"). Nothing was edited.

Legend: PRESENT = equal or better; PARTIAL = exists but weaker/different; MISSING = no equivalent. Priority: P1 must have (old-platform user would notice), P2 should have, P3 nice to have.

Key structural differences to keep in mind
- Legacy is one page with 7 tabs and 4 modals. New is a hash-routed app: `#/` Home, `#/research`, `#/judgments/:id` (reader replaces the Dossier modal), `#/judgments/check`, `#/graph/:id?`, etc. (js/pages/index.js:5-8, each page's `route`).
- New sign-in is a real page; the token is sent as `Authorization: Bearer` on every call (js/api.js:84) and the server enforces permissions (backend/auth.py:267 `require`, server.py:658-1074 `Depends(require(...))`). Legacy never sent the token.
- New sidebar items are filtered by permission (js/ui/sidebar.js:26-33), so "locked tab" screens do not exist; unreachable routes go to `#/forbidden`.

# 4. Ideas to go beyond the legacy platform (tied to SOW)

1. SCitation integration / treatment status (SOW citator): add a `citation_treatments` table (citing_id, cited_id, treatment: followed / distinguished / explained / doubted / overruled / partly overruled / referred to larger bench, paragraph refs, bench size, date). Populate from SCitation feed or a curated import; replace the single `precedent_status` column. UI: treatment badge with count on every result card and in the reader ("Followed 14, Distinguished 3, Overruled by 1"), a "Treatment history" timeline tab in the reader, and a treatment filter in Research with multiple values. Citation check then returns the full treatment list, not one flag.
2. Paragraph-level retrieval and quote verification: store judgment paragraphs (id, judgment_id, para_no, text, FTS5 index). Research shows the best-matching paragraph under each result with highlighted terms ("Para 12: ..."), click opens the reader scrolled to `?para=12`. Complete the "Quote-to-paragraph match" row in Research and Citation check: user pastes a quotation, system returns exact/near match and paragraph number, or "not found in this judgment" (this is the real answer to "zero hallucination").
3. Semantic and natural-language search: hybrid BM25 + embedding retrieval over paragraphs/headnotes (local model to stay air-gapped); query like "can bail be refused solely on the ground of economic offence" returns ranked paragraphs. Add a toggle "Keyword / Meaning" and show which mode produced each hit. Presentation slide 3 promises "Semantic Conceptual Search"; legacy does not deliver it.
4. Saved searches and alerts: server-side `saved_searches` (user, query, filters, name, created, last_run, last_count). Research: "Save this search" button, "Saved searches" list replacing session-only history, optional "Notify me when new judgments match" using the sync history (daily digest on Home and Alerts badge). Add shareable search link `#/research?q=...&court=...&from=...`.
5. Research export: "Export results" (CSV, DOCX bibliography with proper citations and treatment flags, RIS). Add "Copy all citations" for the bench brief and a "Table of authorities" generated from the bench brief (feeds Studio section 15).
6. Bench brief as a first-class object: persist to server (per user/matter), allow notes per authority, reorder, share with chambers/clerk, and one-click insertion in Studio sections 10 and 15 (fixes the broken hand-off in F029).
7. Citation hygiene for pleadings: "Check a document" (F039) that extracts every citation from an uploaded brief/draft, verifies each, flags overruled/not found, offers replacements ("closest corpus match"), and exports a verification report with timestamp and corpus version for the record.
8. Lineage builder: user-entered case or citation -> auto-built lineage using incoming/outgoing `cites` edges and overruled_by chain, with year-ordered timeline, bench size, and holding sentence per node (from curated ratio). Side-by-side paragraph comparison of two judgments from the graph (promised in legacy docs, never built). Curated "learning paths" for faculty/students with notes (`ACADEMIC_NOTES` permission already exists).
9. Dashboard value: "What changed since you last logged in" (new judgments, newly overruled authorities touching your matters), top-cited authorities, search-to-draft conversion for the chamber, corpus coverage by year/court with gaps highlighted (honest data-quality view).
10. Command palette upgrade: type a citation or case name to jump straight to the reader or run a check; recent judgments; keyboard hints on result rows (j/k to move, b to add to brief, o to open).
11. Provenance that is real: store `sha256` of each source PDF at ingestion and the ingestion timestamp; show on the reader; verify on demand ("re-download and compare"). Replaces the legacy static "SHA-256 Validated" claim with something testable (links to s65B/s63 BSA evidentiary value in SOW).
12. Role-aware quick filters: for clerks "my matters' authorities", for faculty "constitution bench only", for students "explainers/ratio only" using existing permissions (`VIEW_RATIO`, `STUDY_LINEAGE`).
